## Findings

### 08-01 — Production canonical and social metadata point to localhost

**Medium · Content / discoverability ·** `/garden/`, `/research/`, all three topic pages, `/about/` and sampled `/cv/`.

1. Open any route above on the public site, for example `/research/number-theory/`.
2. Inspect `link[rel=canonical]`, `meta[property="og:url"]` and `meta[property="og:image"]` in the document head.

**Expected:** The canonical and `og:url` use the public HTTPS origin and route path; the social image points to the production image. This is the production contract in [deploy.md](../../../deploy.md).

**Actual:** Number theory emits `http://localhost:4321/research/number-theory/` for both URL fields and `http://localhost:4321/og/social-card.png` for the image. The other sampled pages likewise point at localhost. Ordinary links still work; the metadata advertises URLs that are not public. Crawler or social-service behavior was not tested. This is the **same known issue** tracked in [QUESTIONS.md](../../../QUESTIONS.md), not a new independent deployment defect. No console errors.

**Evidence:** [Exact live `<head>` values for seven routes](layout-and-citations-evidence.json).

### 08-02 — An unlisted Type query can hide every result without showing the active filter

**Low · UX / accessibility ·** `/garden/?type=preprint`, also `?type=software` and `?type=dataset`.

1. In a foreground browser tab, open `/garden/?type=preprint` directly.
2. Inspect the Type chips, displayed count and empty state. Compare `/garden/?type=paper&tag=water-quality`, where the zero-result intersection is visibly explained by two active filters.

**Expected:** An accepted URL filter is reflected in the visible and programmatic selection, or an unavailable type falls back to **All types** (as an unrecognized value does). The active filter should be apparent without inspecting the URL.

**Actual:** The recognized value is applied and the page says “Showing 0 of 9 items” and “Nothing matches these filters,” but none of the visible Type chips has `aria-current`; only **All areas** is active. There is no chip for the effective type. **Show all work** or **All types** recovers. This does not affect links generated by the current visible chips, so the severity is low. No console errors.

**Evidence:** [Garden state matrix](garden-evidence.json), including supported-empty control and unknown-value fallback.
